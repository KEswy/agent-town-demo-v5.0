# Agent Town V3 改进与开发路线表

> 基线版本：V2.0（2026-07-19）
>
> 目标：在继续坚持“Python 决定规则事实、LLM 负责合法策略与表达”的前提下，让 NPC 更可测、更连贯、更像真实玩家，并把 Demo 提升为可持续迭代的游戏原型。

## 优先级与里程碑

| 标记 | 含义 |
| --- | --- |
| P0 | V3 的基础能力；不先完成就难以判断后续修改究竟变好还是变坏 |
| P1 | 明显改善智能、体验或开发效率，应在基础闭环稳定后推进 |
| P2 | 扩展性与内容型投入，适合核心玩法稳定后再做 |
| S / M / L / XL | 约表示很小、小型、中型、大型工作量；实际排期需在开发前再次拆分 |

| 里程碑 | 建议目标 | 明确不做 |
| --- | --- | --- |
| V3.1 可测智能闭环 | 种子模拟、指标、合法视角信念状态、统一立场摘要、投票校准、LLM 可观测性 | 新角色包、多人联机、大地图扩建 |
| V3.2 连贯体验 | 扩展结构化决策阶段、证据时间线、复盘解释、存档恢复、发言质量与居民关系 | 大规模玩法分叉 |
| V3.3 工程与内容扩展 | 配置工具、发布流水线、模型适配、无障碍、音画反馈和可选内容包 | 在核心指标不稳定时盲目扩量 |

## 推荐的第一个小里程碑

先完成 M01、M02、M03、M04、M06、M09 和 M15。它们组成一条最小闭环：同一随机种子可以重放一局，系统能记录每个 NPC 当时看到了什么、相信什么、为何改变立场，批量结果能显示票型是否过度一致、好人是否过强或过弱、LLM 是否频繁失败。闭环完成前，不建议继续大量增加狼人战术，因为单局体感很难区分真实改进与偶然结果。

V3.1-B 对相同 100 局的首份诊断为：好人胜率 6.00%，平均局长 3.42 天，警长票/放逐票归一化熵分别为 28.25%/22.62%，好人误投率 60.95%，假预言家获得 48.29% 的适用好人警长票并在 72.00% 对局当选。该样本不代表期望胜率，也不作为自动化平衡阈值；后续必须先让 M03/M04 解释信念和立场变化，再通过 M15 多种子校准，不能只针对这一批 seed 调参。

V3.1-C 在不改变上述任何玩法或指标的前提下，为 100 局记录 11,650 条去重证据和 32,343 次信念变化；公开/行动者私有/狼队证据分别为 10,209/358/1,083 条。完整轨迹约 46MB，后续 1000 局平衡任务可关闭详细轨迹。

V3.1-D 继续保持 shadow 模式：公开声明/立场等软证据每天保留 75% 权重，已观察到的公开票型/警徽动作和角色依法知道的私有事实不衰减；私聊只消费 Python 已保存的结构化目标与方向，不从玩家问题或 NPC 回复自由文本推断。

V3.1-E 继续保持 shadow 模式：统一摘要只读取合法 belief 和结构化公开承诺；连续性分类用于定位发言/警长票/放逐票是否脱节，不把小样本一致率或未解释变化率设成自动阈值，也不改变现有胜负与 M02 指标。

V3.1-E 的首份 100 局诊断记录 6,133 次观察，其中 4,516 次可评分，一致率 88.93%、未解释变化率 4.78%，其余 1,617 次为没有合法可比目标的 `unscored`。该结果用于定位 M04-B 候选入口，不代表目标质量线。

V3.1-F 只把普通非警长白天发言设为受控消费者：fallback 沿用合法 stance；LLM 改变目标必须引用新增公开 signal、命中可复现个体扰动，或使用合法声明/规则强制回应的专用原因。私有 belief evidence ID 不进入持久化计划。警长票和放逐票继续保留 shadow，避免在同一小里程碑同时改变三个决策入口。

V3.1-F 同一批 100 局共记录 2,163 次受控发言，其中 1,831 次沿用 stance、141 次合法声明、139 次规则强制回应、52 次无可比立场；规则模拟关闭 LLM，因此公开新证据与个体扰动分支为 0。公开发言未解释变化从 112 次降到 3 次，整体未解释率为 1.68%，但好人胜率降到 2%、好人误投率升到 64.46%。这说明 M04 连续性目标与 M15 判断/票型校准必须分开验收。

V3.1-G 把 M06 的首段范围限定为无权村民：六个仅改变内部真值/来源/未发布结果的变体，逐个对比普通村民玩家公开投影，以及每名普通 NPC 村民的 belief、stance、decision context、continuity 和规则 fallback。固定夹具为 6 个变体 ×（1 个公开投影 + 3 名观察者 × 5 个 actor 投影）=`96` 项并全部一致；公开查验内容变化的负对照必须失败。报告只保留摘要和首个差异路径，不保存隐藏正文。角色合法私有知识的“应该变化”留给 M06-B 单独验收。

## V3 每轮开发的固定验收门槛

| 类别 | 最低要求 |
| --- | --- |
| 规则正确性 | Python 继续是身份、行动、投票、出局、警徽和胜负的唯一事实源 |
| 信息权限 | 好人决策不得读取隐藏身份；公开投影与内部声明来源解耦；新增字段必须补差分测试 |
| LLM 安全 | 所有策略输出有版本化 schema、allowlist、合法性校验和确定性回退 |
| NPC 质量 | 同时看单局可解释性与多种子分布，不能仅凭一局输赢调参 |
| 文档与测试 | 每次功能更新同步根 README、后端 README、路线状态和自动化自检 |
| 运行纪律 | 自动化测试不自动启动常驻 FastAPI 服务；实际后端仍由开发者手动启动 |
